## Required Production Source Characteristics

The future production source must provide:

- complete Catholic 73-book canon
- all chapters and verses
- stable canonical book names, chapter numbers, and verse numbers
- explicit translation identity
- explicit edition/source identity
- language
- source URL and provenance
- license/copyright status and redistribution rights notes
- deterministic machine-readable format
- no silent omissions
- no duplicate canonical references within the same translation
- complete deuterocanonical coverage

## Importer Compatibility

Before this sprint, the Bible importer and audit command supported:

- single chapter JSON: `book`, `chapter`, `verses`
- wrapped multi-book JSON: `books[].chapters[].verses[]`

The selected candidate uses book-level JSON:

- `book`
- `book_title`
- `short_title`
- `chapters[].verses[]`

The importer and audit service now support this shape for future validation/import readiness. This does not approve or import any source.

## Scalability Assessment

Expected future row pattern:

- one `bible_verse` document per verse
- one `bible_chapter` document per chapter

For a complete Catholic Bible, expect roughly:

- 73 books
- about 1,300 chapters depending on versification
- about 35,000 verses depending on edition/versification
- about 36,000 `knowledge_documents`
- one embedding candidate per persisted document after import

Recommendation:

- store source files one per book or one per chapter
- avoid a single monolithic generated file
- pin the source commit
- run audit before import
- import with `--no-embeddings` first in a staging database
- generate embeddings only after document counts and provenance pass verification

## Existing Data And Translation Identity

Local database currently contains:

- `bible_verse`, source name `Bible`, 51 documents, translation metadata missing
- `bible_verse`, source name `Douay-Rheims Bible`, 51 documents, translation `douay_rheims`
- `bible_chapter`, source name `Douay-Rheims Bible`, 1 document, translation `douay_rheims`

There are 51 duplicate plain references for John 1 across `Bible` and `Douay-Rheims Bible`. These are not same-source duplicates, but they can make plain reference lookup ambiguous.

Do not delete or alter existing data in this sprint. Before a full Douay-Rheims import, plan a cleanup migration that either:

- tags legacy `Bible` records with an explicit legacy source identifier, or
- archives/removes legacy duplicated fixture records in a controlled migration, or
- updates reference lookup APIs to require or prefer translation/source identifiers when duplicates exist.

## Knowledge Graph Impact

Bible import alone will not create theological graph edges unless source metadata supplies explicit references.

Current graph resolvers use explicit metadata such as:

- `scripture_references`
- `cross_references`
- `internal_references`
- `catechism_references`
- `church_father_references`

The Original Douay-Rheims candidate includes `cross_refs` objects using original abbreviations. These should not be blindly converted to graph edges until abbreviation parsing and normalization are explicitly implemented and tested. No inferred theological edges should be generated.

Only after that should the source inventory be considered for approval.
